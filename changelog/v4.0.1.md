# Changelog - Version 4.0.1

A reporting fix for a system-wide install. No trust-boundary or security change.

### Fixed
*   **`status` and `agentsecrets doctor` now report the real daemon mode on a system install.** A system store is `0600` and daemon-owned, so an unprivileged CLI could stat it but not open it. `ConfigPath()` keyed on readability and fell back to the per-user path, so `keychain-auth status` reported `Mode: user` and `RequiresSudo: false`, and `doctor` validated the wrong file's permissions. System installs are now identified by the *presence* of the store, not by whether this process may read it. `queryDaemonToCheck` and the live verification round-trip were already correct; only the local path probe was wrong.
