# v4.0.2

A small release focused on client integration and release integrity. It adds
generic self-description, removes a silent request-size mismatch, and signs
published artifacts. No AgentSecrets-specific policy was added to the daemon.

## What is new

- `keychain-auth identity [--json]` reports this binary's version, SHA-256 of
  the running executable, store mode, config path, socket path, PID, and
  protocol version. A client can compare it with the peer process before
  sending secrets.
- A read-only `status` action over the socket. It reports the calling peer's
  registration state, hash currency, and service names, plus the daemon's
  version, mode, and paths. It is answered before the registration denial, so
  an unregistered binary can diagnose itself without reading a root-owned
  trust store.
- The request decoder accepts frames up to 10 MiB, matching the response side.
  Large batch writes with per-key policy blobs no longer fail as malformed.
  The limit is published in `docs/integration_spec.md`.
- `checksums.txt` and every release archive are signed with `cosign sign-blob`.
  Sigstore bundles are published beside the artifacts. See
  `docs/signing.md` for verification commands.
- `keychain-auth ensure-running --json` and `keychain-auth restart --json` own
  service detection and return the dialable socket. The daemon writes a PID
  file beside its socket so a detached instance can be stopped without
  scanning processes.
- `keychain-auth self-update [--version X] --json` downloads a release, checks
  its SHA-256 against `checksums.txt`, and replaces the binary. Windows writes
  `<binary>.new` for the caller to finish.
- The README is shorter and easier to scan.

## Upgrading

No configuration changes are required. Existing clients keep working.

New clients can feature-detect the `status` action. An older daemon answers
unknown actions with `malformed_request`, which should be treated as "status
unsupported" and fall back to local diagnostics.

## What this does not do

Sigstore proves provenance. It is not Microsoft Authenticode and does not
create Windows SmartScreen reputation.

`ensure-running` and `restart` report "not supported" on Windows. Use the
Windows service manager there. This release does not move a client's policy or
recovery decisions into the daemon.
